# Soul Fork Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 登录用户在他人已上架 Soul 详情页一键 Fork，在本人账号下得到完整副本（默认 UNLISTED），详情页展示 `Forked from handle/slug` 溯源。

**Architecture:** 专用 `POST /api/packs/[handle]/[slug]/fork`（Session 鉴权）；核心逻辑集中在 `web/src/lib/pack-fork.ts`（校验源、复制库表行、用 `readStoredFile` + 既有 `write*` 复制存储对象）；`Pack` 增加 fork 溯源字段；详情页增加客户端 Fork 按钮与作者可见 Tip 条。

**Tech Stack:** Next.js App Router、Prisma、既有 `storage` / `syncPackDerivedAfterSourceChange`、`publish-rate-limit`、`next-intl`。

**Spec:** [`docs/superpowers/specs/2026-04-28-soul-fork-design.md`](../specs/2026-04-28-soul-fork-design.md)

- [ ] **Step 2: 实现校验链（先 rate limit 再查源）**

在 `forkPackForSessionUser` 内顺序：

1. `const rl = checkPublishRateLimit(sessionUserId)`；若 `!rl.ok` 返回 `{ ok: false, error: "rate_limited", retryAfterSec: rl.retryAfterSec }`。
2. 加载用户：`db.user.findUnique({ where: { id: sessionUserId }, select: { handle: true } })`；无 `handle?.trim()` → `{ ok: false, error: "no_handle" }`。
3. `const newSlug = newSlugRaw.trim()`；`assertValidSlug` 包在 try/catch，失败 → `{ ok: false, error: "invalid_slug" }`。
4. `db.pack.findFirst({ where: { slug: newSlug, authorId: sessionUserId } })` 若存在 → `{ ok: false, error: "slug_taken" }`（**P2002 不应依赖**，先查显式）。
5. 加载源 pack：`db.pack.findFirst({ where: { slug: sourceSlug, author: { handle: sourceHandle } }, include: { author: { select: { id: true } }, markdownFiles: true, binaryFiles: true } })`。不存在 → `source_not_found`。
6. 若 `source.authorId === sessionUserId` → `cannot_fork_own`。
7. 若 `source.visibility !== PackVisibility.LISTED` 或 `source.authorDashboardHiddenAt != null` → `source_not_listed`（与详情页「仅 LISTED 且未 dashboard 隐藏」对齐）。

- [ ] **Step 3: 复制存储与写入新 Pack（`newId` 先定，失败清理）**

1. `const newId = randomUUID()`；`await ensurePackDirs()`。
2. **Binary（须先有 `newId`，再写入存储）**：对每条 `source.binaryFiles`：`buf = await readStoredFile(row.storageRef)` → `storageRefNew = await writeBinaryForPack(newId, row.path, buf)`，收集 `{ path, storageRef: storageRefNew, byteSize: buf.length, sha256: crypto.createHash("sha256").update(buf).digest("hex") }`。
3. **Avatar（可选）**：若 `source.avatarRelPath`，`buf = await readStoredFile(...)` → `avatarRelPath = await writeAvatarForPack(newId, ext, buf)`，否则 `avatarRelPath = null`。
4. **Showcase 图**：`normalizeShowcaseImageRefs(source.showcaseImageRefs)` 逐张 `readStoredFile` + `writeShowcaseImageForPack(newId, randomUUID(), ext, buf)`，拼出新的 `ShowcaseImageRef[]` JSON；**正文**沿用 `source.showcaseMd`。
5. **单次 `pack.create`**（含嵌套）：`data: { id: newId, slug: newSlug, title/summary/copy 自源, showcaseMd/showcaseImageRefs, avatarRelPath, authorId: sessionUserId, visibility: UNLISTED, zipRelPath: null, packFilePaths: [], forkedFromPackId/Source 快照字段, markdownFiles: { createMany: source.markdownFiles 映射 }, binaryFiles: { createMany: 步骤 2 收集的数据 } }`。若 Prisma nested `createMany` 与 UUID 兼容有问题，改为先 **`pack.create`** 仅 pack 元数据 + fork 字段（`showcaseImageRefs`/avatar 可分步 **`pack.update`**），再 **`createMany` md/bin**，原则不变：**先有 Pack id，再写入外键关联行**。
6. `await syncPackDerivedAfterSourceChange(db, newId)`。
7. `recordPublishSuccess(sessionUserId)`。
8. 构造 `viewPath` 字符串：`/packs/` + `encodeURIComponent(handle)` + `/` + `encodeURIComponent(newSlug)`，对齐 `createEmptyPackForUserId`；返回 `{ ok: true, handle, slug: newSlug, viewPath }`。

失败时：对已创建的 `Pack` 行 `delete`（级联删 md/bin），并对已写入存储的 orphan 文件按需 `removeStoredFile`（与项目错误处理惯例一致）；响应 `{ ok: false, error: "fork_failed" }`，`console.error` 附带 cause。

### Task 3: HTTP API `POST .../fork`

**Files:**
- Create: `web/src/app/api/packs/[handle]/[slug]/fork/route.ts`

- [ ] **Step 1: 实现 `route.ts`**

```typescript
import { NextResponse } from "next/server";
import { forkPackForSessionUser } from "@/lib/pack-fork";
import { prisma } from "@/lib/prisma";
import { readSessionUserId } from "@/lib/session";

export async function POST(
  req: Request,
  ctx: { params: Promise<{ handle: string; slug: string }> }
) {
  const userId = await readSessionUserId();
  if (!userId) {
    return NextResponse.json({ error: "unauthorized" }, { status: 401 });
  }

  let body: unknown;
  try {
    body = await req.json();
  } catch {
    return NextResponse.json({ error: "invalid JSON" }, { status: 400 });
  }
  const slug =
    typeof body === "object" && body !== null
      ? String((body as Record<string, unknown>).slug ?? "").trim()
      : "";

  const { handle, slug: sourceSlug } = await ctx.params;

  const result = await forkPackForSessionUser(
    prisma,
    userId,
    decodeURIComponent(handle),
    decodeURIComponent(sourceSlug),
    slug
  );

  if (!result.ok) {
    const map: Record<string, number> = {
      no_handle: 400,
      invalid_slug: 400,
      slug_taken: 409,
      source_not_found: 404,
      source_not_listed: 404,
      cannot_fork_own: 403,
      rate_limited: 429,
      fork_failed: 500,
    };
    const status = map[result.error] ?? 500;
    const headers =
      result.error === "rate_limited" && result.retryAfterSec
        ? { "Retry-After": String(result.retryAfterSec) }
        : undefined;
    return NextResponse.json(
      { error: result.error },
      { status, headers }
    );
  }

  return NextResponse.json({
    ok: true,
    handle: result.handle,
    slug: result.slug,
    viewPath: result.viewPath,
  });
}
```

若 `ctx.params` 在项目中不用 `decodeURIComponent`（其它 route 直接 `params.handle`），与 `web/src/app/api/packs/[handle]/[slug]/publish/route.ts` 保持一致。
