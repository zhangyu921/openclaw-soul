# P1-B-2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Web 上可编辑 pack 展示标题；CLI `publish` 交互减负（先问是否整 workspace、不再问 title/summary/avatar）、统一默认 title 推导（IDENTITY Name → slug），并在上传成功后提示用户去站点完善与上架。

**Architecture:** 扩展 `PATCH /api/packs/[handle]/[slug]` 支持可选 `title`/`summary` 部分更新；详情页新增与 `PackSummaryEdit` 同风格的标题编辑客户端组件。CLI 在 `sourceDir` 与 `slug` 确定后**单一位置**计算 `title`（`--title` 优先，否则 `readIdentityDefaults`，否则 `slug`），并重构 `publish-wizard.ts`：先 `confirm` 整 workspace，再条件调用现有根文件多选；移除元数据提问与成功后的固定 stderr 文案。

**Tech Stack:** Next.js App Router、Prisma、`@inquirer/prompts`、现有 `packages/cli` 测试（Vitest 等，以仓库为准）。

**Spec:** [`docs/superpowers/specs/2026-04-03-p1-b-2-design.md`](../specs/2026-04-03-p1-b-2-design.md)

### Task 1: Web — PATCH 支持 `title` 与部分更新

**Files:**
- Modify: `web/src/app/api/packs/[handle]/[slug]/route.ts`

- [ ] **Step 1:** 定义常量 `MAX_TITLE_LENGTH = 256`（与 spec 一致），与现有 `MAX_SUMMARY_LENGTH` 并列。
- [ ] **Step 2:** 将 PATCH 请求体解析为：允许 **`title` 与/或 `summary`**；若 JSON 中两者皆缺，返回 `400` 及明确 `error`。
- [ ] **Step 3:** 若提供 `title`：`typeof` 校验、trim、非空、长度 ≤ `MAX_TITLE_LENGTH`；`prisma.pack.update` 只设置传入字段（`data: { ... }` 按需合并）。
- [ ] **Step 4:** 若提供 `summary`：保持现有 trim/null/长度逻辑。
- [ ] **Step 5:** 响应 JSON 返回已更新的字段（例如 `{ title, summary }` 或仅返回变更字段），保证 `PackSummaryEdit` 仍可用（若只 PATCH `summary`，行为与现网一致）。

**Verify:** 本地对作者 session `curl` 或 Vitest：仅 `{ "title": "x" }`、仅 `{ "summary": "y" }`、两者同时；非作者 403；超长 title 400。

### Task 3: CLI — `runPublishWizard` 行为调整

**Files:**
- Modify: `packages/cli/src/publish-wizard.ts`

- [ ] **Step 1:** 在 `promptPackRootFiles` **之前**插入：`confirm({ message: "是否上传整个 workspace 目录（含子文件夹，等同 --full）？", default: false })`（文案可与 spec 略调，**默认 false**）。
  - `true` → 返回 `{ fullZip: true }`，**不调用**原 checkbox 根文件流程。
  - `false` → 调用现有 `promptPackRootFiles`（保留内部「整目录」选项与否：见 Step 2）。
- [ ] **Step 2:** 子集模式下，现有 `buildSubsetChoices` 仍含「整个 workspace」项。Spec 要求先单选整包；可选实现：
  - **A（推荐）**：子集分支里 **移除** `PACK_FULL_SENTINEL` 选项及相关 `buildFullDisplayChoices` 循环（整包仅在第一步 confirm），简化代码路径；或
  - **B**：保留 sentinel 作第二道保险（与 spec「先单选」略重复）—— **不推荐**，除非产品坚持双入口。
- [ ] **Step 3:** 删除 `runPublishWizard` 中所有 **Display title**、`Customize summary or avatar?`、summary/avatar 输入；删除 `missingSlugOrTitle` 中与 **title** 相关的分支（仅缺 slug 时仍问 slug；缺 title 不再问）。
- [ ] **Step 4:** 调整 `WizardPublishResult`：**不再返回 `title`**（或 `title` 可选且不再由向导填充）；**不再返回** `summary`/`avatar` 除非仍从 `params` 透传 CLI 已传入的 `summary`/`avatar`（`index` 传入的 opts 保留）。
- [ ] **Step 5:** 处理 `missingSlugOrTitle` 变量：向导触发条件改为仅 **`!slug`**（或等价），不再依赖 `!title`。

**Verify:** 手动跑 `pnpm run ocs -- publish`（TTY）：顺序为 来源 → slug → 整 workspace confirm → 子集多选；无 title/summary/avatar 提问。

### Task 4: CLI — `index.ts` 统一 `title` 与向导衔接

**Files:**
- Modify: `packages/cli/src/index.ts`

- [ ] **Step 1:** 在 **`sourceDir` 已解析**且 **`validateSlug(slug)` 之后**（或紧接 `assertWorkspaceRootSoulFileExists` 前后，保证与 `readIdentityDefaults` 目录一致），设置：

  ```ts
  const explicitTitle = (opts.title ?? "").trim();
  const title =
    explicitTitle ||
    readIdentityDefaults(sourceDir)?.displayName ||
    slug;
  ```

  **删除** 原在 wizard 之前仅针对 `slug && !title` 的 identity 块（约 361–374 行），避免重复与顺序错误。

- [ ] **Step 2:** `runPublishWizard` 返回后：**不要**用 `w.title` 覆盖（若向导不再返回 title）；`summary`/`avatar` 仅来自 `opts` / 向导透传的 CLI 参数（向导不再采集则仅 opts）。
- [ ] **Step 3:** 确认 `publishPack({ title, ... })` 使用上述 `title`。

**Verify:** `--slug foo` 无 `--title`：有 IDENTITY Name 则上传 title 为 Name；无 IDENTITY 则为 `foo`。`--title Bar` 覆盖为 `Bar`。

- **向导双入口整包**：Task 3 Step 2 建议移除子集列表中的「整目录」选项，避免与第一步 confirm 重复。
- **`WizardPublishResult.title`**：所有引用 `w.title` 处需删除或改为统一 `title` 解析。
