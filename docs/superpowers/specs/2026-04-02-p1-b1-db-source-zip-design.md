# P1-B-1：库表真源与按需 zip（设计稿）

**日期**：2026-04-02  
**状态**：已定稿（待实现）  
**路线图**：[`docs/ROADMAP.md`](../../ROADMAP.md) **P1-B-1**；**P1-B-2**（详情页「妙用」、在线富编辑与截图素材）**不在**本 spec 范围内。

---

## 1. 背景与目标

**背景**：当前 pack 的「下载物」以 **Blob 存储的 zip**（`zipRelPath`）为唯一来源；正文预览依赖 zip 内提取（如 `soulPreviewMd`、`packFilePaths`）。产品需要 **全部 Markdown 文件落库**，以支持后续 **预览与在线编辑**，同时 **`apply` 仍是一键 zip 解压到 workspace**。

**目标**

- **库表真源**：pack 内 **每一个 `.md` 文件** 在数据库中有 **可独立读写** 的记录（路径 + UTF-8 正文 + 元数据如 `updatedAt`），满足后续预览与编辑需求。
- **非 Markdown 文件**：不进入 md 表；以 **对象存储 + 路径映射**（或等价结构）保存，保证按需组 zip 时能按路径装入。
- **按需 zip（方案 1）**：`GET /api/packs/<handle>/<slug>/download`（及与 CLI 契约一致的 zip URL）在 **库表模式** 下 **由服务端从库 + Blob 组装 zip 流**；在 **Blob 模式** 下行为与 **现网一致**（读取已存 zip）。**CLI `apply` 不改为多段 manifest 拉取**。
- **完全兼容**：未迁移、仍仅有 Blob zip 的 pack **继续走现有下载路径**（见 §4）。
- **迁移**：以 **维护者脚本 / 一次性任务** 为主，将历史 zip 摄入库并切换模式；**不**在本阶段要求作者自助迁移 UI（避免无效分支堆积）。

**非目标**

- **P1-B-2**：详情页「妙用」区块、富文本编辑器、对话截图等 **站点产品面**——**不纳入**本 spec。
- **作者自助迁移**（Dashboard 按钮等）：**不纳入** MVP；若后续需要，单独 plan。
- **彻底删除**历史 Blob zip 对象：非必须；可在实现计划中约定是否保留作灾备。

---

## 2. 数据模型（原则）

以下为 **语义要求**；具体 Prisma 表名、字段名、索引在实现计划中定。

| 概念 | 说明 |
|------|------|
| **Pack 交付模式** | 每个 `Pack` 需能判定：**Blob 模式**（仅依赖 `zipRelPath` 等现有字段）与 **库表模式**（md 与二进制映射为真源，按需组 zip）。实现可用枚举或布尔，与现有 `visibility` 正交。 |
| **Markdown 行** | 每个 pack 内 **相对路径**（与 zip 内路径一致，规范化后唯一）对应 **一条记录**，正文为大文本；**全包所有 `.md` 文件均须有条目**（库表模式下）。 |
| **二进制行** | 每个非 md 路径对应 **存储引用**（Blob URL、对象键或项目内统一 `zipRelPath` 子路径策略），使组 zip 时能读出字节流。具体选型（与现有 `writeZipForPack` / Vercel Blob 一致与否）在 **实现计划中选定一条**，本 spec 不预决。 |
| **体积与上限** | 与现网一致：**整包 zip ≤ 2 MiB**（见 README / API）。库表模式下须在 **写入 / 迁移 / 组 zip** 等环节校验，避免超标；具体校验点由实现计划列出。 |

**与现有字段关系**

- `soulPreviewMd` / `packFilePaths` 等可在库表模式下由实现决定：**继续填充作缓存** 或 **改为从 md 表派生**；本 spec 要求 **预览与编辑的真源为 md 表**，不以 zip 内提取为长期唯一来源。

## 3. HTTP 行为

**Zip 下载**（现有路径，CLI 依赖）：

- **路由**：`GET /api/packs/<handle>/<slug>/download`（与响应 JSON 中的 `downloadPath` 一致）。
- **鉴权**：与现网 **一致**（如 `LISTED` 匿名可下；`UNLISTED` 需作者 Bearer 等——以当前 `visibility` 实现为准）。
- **分支**：
  - **Blob 模式**：与当前实现一致（从存储读 zip 并返回）。
  - **库表模式**：从 md 表 + 二进制映射 **流式生成** `application/zip`；失败时返回 **明确错误**（状态码与 JSON body 在实现计划中写死，避免静默空包）。

**预览 API**

- **本阶段不强制交付**面向浏览器或公开的「按路径读 md」HTTP API。必须交付的是 **md 表真源**（§2），供后续 **P1-B-2** 或站内读取使用。
- 若实现计划在 P1-B-1 内顺带增加 **作者侧或内部只读接口**，须在实现计划中单独列出并验收；**不作为**本 spec 的默认必做项。

---

## 4. CLI `apply`

- **契约不变**：先拉 pack 元数据（含 zip 下载 URL），再 `downloadToFile` → 解压 → 备份与写 `openclaw.json`。
- **服务端升级**：同一下载 URL 在库表模式下由服务端 **按需生成** zip，CLI **无感**。

---

## 5. 迁移（维护者脚本）

- **输入**：指定 pack 列表或全量；从 Blob **读取现有 zip**。
- **步骤（逻辑）**：解压 → 识别所有 `.md` → 写入 md 表 → 非 md 写入二进制映射 → 将 Pack 标为 **库表模式**。
- **错误**：某包解压失败、超大、路径冲突时，脚本应 **失败可辨**；不半切换状态（实现计划定义事务边界）。
- **幂等**：对同一 pack **重复执行**迁移的预期行为（跳过 / 全量覆盖 / 仅补缺）在实现计划中写死，避免半迁移状态难以重跑。
- **兼容**：未执行迁移的 pack **保持 Blob 模式**，行为与 §3 **Blob 分支**一致。

---

## 6. 错误处理与测试（验收原则）

- 库表模式下 **缺 md 条目、二进制缺失、编码错误、超 2 MiB**：组 zip 须 **失败可测**，不向用户返回损坏 zip。
- **回归**：仅 Blob 的旧 pack：`apply` 与画廊/详情行为 **不变**。
- **迁移等价标准（默认）**：解压后的 **相对路径集合** 与 **每个路径下的文件字节内容** 与原 zip **一致**。zip 内 **条目顺序**、**中央目录时间戳** 等元数据差异 **不** 作为回归失败条件。若因平台限制无法做到字节级一致，须在实现计划中列出 **允许的偏差** 与验收方式。

---

## 7. 与 P1-A、P1-B-2 的边界

- **P1-A `visibility`**：本 spec **不改动** 可见性语义；下载与详情仍遵守 `UNLISTED` / `LISTED` 规则。
- **P1-B-2**：详情页「妙用」、截图素材、在线编辑 **产品化**——依赖本 spec 的 **md 落库** 能力，但 **UI 与交互不在本 spec**。
