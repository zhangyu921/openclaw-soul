# P2-T-1：画廊 card 展示 Soul 被查看次数 — 设计说明

**日期**：2026-04-22  
**状态**：待实现（与 draft plan PR 同步）  
**Implementation plan**：[`../plans/2026-04-22-p2-t-1.md`](../plans/2026-04-22-p2-t-1.md)

---

## 1. 目标与成功标准

- **用户价值**：在首页 **画廊** 中快速感知哪些 Soul 被浏览较多（热度信号）。
- **成功标准**：
  - 数据库有 **按 Pack 维度的持久化** 非负整数计数；
  - **他人**（非作者）打开详情页时计数 +1，作者本人进入 **不** 增加；
  - 首页 card **标题行**右侧在 **>10** 时显示，≤10 时该位置 **不出现** 数字或占位。

---

## 2. 背景与约束

- 画廊为 `web/src/app/[locale]/page.tsx` 的 masonry card；详情为 `.../packs/[handle]/[slug]/page.tsx` RSC。
- 已否定的方向：**仅客户端 state** 计数（不持久、无法满足列表展示）；**按会话 cookie 强去重**（首轮不实现，可后续 P2+）。

---

## 3. 交互与展示

- **位置**：`CardHeader` 内 `CardTitle` 所在行：采用 `flex items-start justify-between gap-2`，标题区 `min-w-0` 仍 `line-clamp-2`；右侧为 **次数字**（`text-xs text-muted-foreground tabular-nums`），可与 `lucide-react` 的 `Eye` 小图标同组，避免与链接整卡可点冲突（数字不是单独链接）。
- **阈值**：`count > 10` 才渲染右侧区域；9、10 均不显示。
- **i18n**：`home` 命名空间增加一条带占位 `{count}` 的短文案（如 en：`{count} views`、zh：`{count} 次浏览`），避免复用 pack 域文案。

---

## 4. 技术方案要点

- **Schema**：`Pack.profileViewCount`：`Int` `@default(0)`，`@map` 可选；不建立额外索引（按主键更新）。
- **Increment 时机**：在详情页 RSC 中，在 `notFound` 已排除且 pack 行已解析后，若当前登录用户 **不是** `pack.authorId`，执行 `prisma.pack.update({ where: { id }, data: { profileViewCount: { increment: 1 } } })`（或等价 raw）。**未登录访客** 应计数 +1。作者访问：`sessionUserId === pack.authorId` 时跳过。
- **竞态与性能**：单请求一次 increment；不阻塞首屏可改为 `void prisma...`  fire-and-forget 仅在可接受时采用——**默认**仍 await，避免进程退出丢写；高并发可接受行级写锁。
- **开发环境**：Next/React 可能对 RSC 重复执行导致 **重复** increment；若需缓解可在后续加「每日每 IP 一行的简易 dedupe 表」；首轮在 plan 的验收中注明**允许开发双计**，生产以单实例行为为准，或加环境变量 `PROFILE_VIEW_DRY_RUN` 由维护者自测（**可选**，若引入则写入 plan 的测试段）。

---

## 5. 错误处理

- `increment` 失败**不应**导致详情页 500；`try/catch` 记录（或 `console.error` 在服务端）后仍渲染详情。

---

- 不修改 `apply`、zip、MEMORY 或 CLI。
