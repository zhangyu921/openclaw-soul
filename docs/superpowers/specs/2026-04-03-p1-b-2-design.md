# P1-B-2：上传体验与 CLI 向导减负（设计稿）

**日期**：2026-04-03  
**状态**：已定稿（待实现）  
**范围**：`web/`（pack 详情、PATCH API）、`packages/cli`（`publish` 交互向导、非交互默认 title、成功提示）

**决策摘要**：采用 **方案 1**（交互减负 + 保留 `--title` / `--summary` / `--avatar` 作可选逃生口）；**默认 title** 在 CLI 侧为 **`readIdentityDefaults(sourceDir)?.displayName`（有则用之），否则与 slug 一致**（再交由服务端存储；与服务端 `titleRaw || slug` 互为兜底）。

---

## 1. 背景与目标

**背景**：`publish` 交互向导仍询问 Display title、summary、avatar；与「元数据以 Web 为主、减少一次 publish 就要完美」的 P1 方向不一致。详情页标题只读，无法在站内改展示名。

**目标**

- **Web**：作者可在 pack 详情页编辑 **Display title**（映射 `Pack.title`）。
- **CLI 交互**：不再询问 Display title、summary、avatar；仍收集 **slug**、**来源目录**，并调整 **文件范围** 提问顺序（见 §3）。
- **CLI 默认 title（不向用户提问时）**：解析 workspace 根目录 `IDENTITY.md` 的 **Name**（与现有 `readIdentityDefaults` 一致）→ 有则作为 `title` 上传；**无**则 **`title = slug`**（与当前 API `titleRaw || slug` 对齐）。
- **CLI 非交互 / 脚本**：保留 **`--title` / `--summary` / `--avatar`**；若显式传入则优先于默认 title 逻辑。
- **上传成功后**：在现有成功输出基础上，**固定提示**用户到 **Web** 完善展示标题、简介、头像，并按需 **上架（LISTED）**。

**非目标**

- 改 P1-B-3（详情正文大编辑、截图等）。
- 移除或弱化服务端对空 title 的 `slug` 兜底（保持兼容）。

---

## 2. Web：Display title 编辑

### 2.1 API

- 扩展 **`PATCH /api/packs/[handle]/[slug]`**（session 作者校验，与现有 summary PATCH 一致）：
  - 请求体允许包含 **`title`**（字符串）与/或 **`summary`**（与现有一致）。
  - **`title`**：trim 后非空；长度上限在实现中用常量约束（`Pack.title` 为无长度限制的 `String`，API 侧需防滥用，例如 **≤256** 字符，与 `summary` 上限风格一致即可）。
  - 可 **仅 PATCH `title`**、**仅 PATCH `summary`**，或 **两者同时**；避免「必须带 summary」的硬性要求（若当前实现强制 `summary` 字段存在，可改为「至少包含 `title` 或 `summary` 之一」或分别允许部分更新——以实现时最小改动为准）。

### 2.2 UI

- 详情页作者视图：在现有只读标题区域提供 **行内编辑** 或 **编辑按钮 + 保存**（风格对齐 `PackSummaryEdit`）。
- 保存成功后更新展示；错误时 toast 或行内错误文案。

---

## 3. CLI：向导交互（文件范围 + 去掉元数据提问）

### 3.1 顺序（相对当前实现）

1. **来源**：保持现有「Current workspace / Other directory」等逻辑。
2. **Slug**：保持现有输入与校验。
3. **是否上传整个 workspace 目录**（**单选 / confirm**，**默认「否」**）：
   - **是** → 等同 **`--full`**，**不再展示**根文件多选步骤。
   - **否** → 进入 **根目录文件多选**（行为与当前子集模式一致：`SOUL.md` 必选、`IDENTITY`/`MEMORY`/extras 等规则以 **当前已实现** 的 `publish-wizard` / P1-B-1 相关逻辑为准，本 spec 不重复定义每一勾选默认值，除非与现网冲突时再开补丁 spec）。
4. **不再出现**：Display title、summary、avatar 的交互提问（含「Customize summary or avatar?」整段）。

### 3.2 默认 title 的计算（无用户输入、未传 `--title`）

在 **`sourceDir` 已解析** 且将调用 `publishPack` 前：

- `title = (opts.title?.trim()) || readIdentityDefaults(sourceDir)?.displayName || slug`  
  （`slug` 已 trim 且合法。）

与 **服务端** `title = titleRaw || slug` 一致：CLI 若发送空字符串，服务端仍会用 slug。

### 3.3 保留 CLI  flags

- **`--title` / `--summary` / `--avatar`**：行为保持为可选覆盖；文档中说明「展示信息更推荐在网页修改」。

---

## 4. 上传成功提示

- 在 **`viewUrl`（或等价）已输出之后**，追加 **简短固定文案**（中英文择一或中英两行，与仓库 CLI 风格一致），例如要点：
  - 打开链接，在网页上可修改 **展示标题、简介、头像**；
  - 需要对外可见时，在网页上 **上架**。
