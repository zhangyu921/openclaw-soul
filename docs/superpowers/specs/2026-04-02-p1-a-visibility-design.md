# P1-A：上架节奏与 `visibility`（设计稿）

**日期**：2026-04-02  
**状态**：已定稿（待实现）  
**路线图**：[`docs/ROADMAP.md`](../../ROADMAP.md) P1-A；**P1-B**（详情「妙用」、库表真源与按需 zip）**不在**本 spec 范围内。

---

## 1. 背景与目标

**背景**：当前 `POST /api/packs` 创建即对画廊公开；仅靠 `revokedAt` 表达「下架」，与「从未上架的草稿」在模型上混用，与产品心智（**未公开 = 仅作者**，下架与草稿同一可见性类）不一致。

**目标**

- 引入 **`visibility` 枚举** 作为对外可见性的**唯一真源**（至少 `UNLISTED` | `LISTED`）。
- **默认新建为 `UNLISTED`**（草稿）；作者登录后可访问 **与现有一致 path** 的详情 **`/packs/<handle>/<slug>`**；**匿名 / 未登录 → 404**；**不进画廊**。
- **CLI**：默认上传为未公开；提供 **一次上传即公开** 的参数；**交互式**须提示当前为草稿并说明公开参数。
- **`apply`**：目标为 `UNLISTED` 时，**TTY 下先提示「当前为草稿/未公开」并确认** 再继续；非交互行为与现有 `-y` 惯例对齐（在实现计划中写死）。
- **迁移**：从现有 **`revokedAt` 推导** 初始 `visibility`，迁移后业务逻辑**不再依赖** `revokedAt`（列可删除或只读存档，实现计划定）。

**非目标**

- **彻底删除**（对外如同从未存在）：**不做**。
- 作者在 UI 上区分「从未公开」与「曾公开后下架」：**不做**（统一 **未公开** + 单一 **上架到画廊**）。
- **P1-B**：站内编辑正文、素材、`visibility` 以外的「库表真源 / 按需 zip」——**不纳入**本 spec。

---

## 2. 数据模型

| 概念 | 说明 |
|------|------|
| `LISTED` | 画廊可见；匿名可访问详情（在未被其他规则拦截的前提下）。 |
| `UNLISTED` | 仅作者可见（同 path）；匿名 **404**；**不进** 画廊 GET 列表。 |

**迁移**

- `revokedAt != null` → 初始 `visibility = UNLISTED`。
- `revokedAt == null`（历史行）→ 初始 `visibility = LISTED`（迁移前线上行为等价于「已公开」）。

**下架**：将 `visibility` 设为 `UNLISTED`，**不再**写入 `revokedAt`。现有 `POST .../revoke` 应改为该语义或内部委托同一实现，避免两套规则。

---

## 3. HTTP API 与 Web

- **`POST /api/packs`（multipart）**：支持显式传入 `visibility`（或等价字段），**默认 `UNLISTED`**；可 **`LISTED`** 表示一次上传即公开。响应体带当前 `visibility`，供 CLI 展示。
- **上架**：`UNLISTED` → `LISTED`（例如 `POST` 或 `PATCH` 专用路由，路径与现有 REST 风格对齐）。
- **下架**：`LISTED` → `UNLISTED`（与 revoke 合并语义）。
- **画廊 `GET`**：仅 `visibility === LISTED`（且作者 handle 等既有条件不变）。
- **详情页**：`UNLISTED` 时仅 **会话用户为作者** 可渲染；否则 **404**。
- **下载**：`UNLISTED` 时仅 **作者鉴权**（token / 会话）可下载；匿名拒绝（状态码在实现计划中统一为 401 或 404 之一）。

**Dashboard 衔接**：既有 [`2026-04-01-dashboard-overview-design.md`](./2026-04-01-dashboard-overview-design.md) 中「公开中 / 已下架」等表述在实现 P1-A 时应改为基于 **`visibility`**（或产品文案「公开中 / 未公开」），**不再**以 `revokedAt` 为展示真源。

---

## 4. CLI

- **默认**：上传成功为 **`UNLISTED`**。
- **参数**：增加 **直接公开**（如 `--public` 或与 `visibility` 对齐的命名）。
- **交互式（TTY）**：成功后提示当前为 **草稿/未公开**，并提示如何用参数一次公开。

---

## 5. `apply` 行为

- 若 registry 返回目标 pack 为 **`UNLISTED`**：在下载解压前 **TTY 提示并确认**；**`-y` / 非交互** 与仓库内其它确认行为一致（实现计划写死）。

---

## 6. 边界与实现决策（需在实现计划中落地）

- **`--replace` / 同 slug 更新**：新上传默认 **不改变** 已有 `LISTED`/`UNLISTED` 除非显式传参；避免误将已公开包打回未公开（除非提供专门开关）。
- **发布频率限制**：建议 **未公开上传仍计入** 成功发布次数（防滥用）；若产品改为未公开不计入，须在实现计划中单列并文档化。
- **测试**：迁移；画廊过滤；匿名详情 404；作者详情与下载；CLI 与 `apply` 提示契约。

---
