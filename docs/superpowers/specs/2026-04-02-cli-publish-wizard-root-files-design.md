# CLI `publish`：workspace 根文件向导与默认子集（设计稿）

**日期**：2026-04-02  
**状态**：已定稿（待实现）  
**范围**：`packages/cli`（`publish` 交互向导、非交互默认子集、前置校验）

---

## 1. 背景与目标

**背景**：`publish` 交互向导（`promptPackRootFiles`）中「整目录」选项在列表末尾；根文件默认含 `MEMORY.md`（存在即勾选）；整目录与多选同时出现时的互斥仅靠「整目录优先」静默覆盖，易误解。

**目标**

- **整目录**选项排在**第一位**，**不默认勾选**（用户一眼可见，默认仍为「根文件子集」模式）。
- **子集模式**下：`SOUL.md` **必选**（不可取消）；**`IDENTITY.md` 若存在则默认勾选**；**`MEMORY.md` 与其它可选根文件一律不默认勾选**（用户显式勾选才打入 zip）。
- 用户勾选 **整目录** 后：**不再**用「提交时校验报错」表达互斥；改为 **整目录选中时，其余根文件选项变为不可选，且全部呈现为已勾选**（表示「整包纳入」；仅整目录一项可操作，用户可取消整目录回到子集模式）。
- **非交互** `publish`（未走向导、且非 `--full`）：默认子集为 **`SOUL.md` + `IDENTITY.md`（当根目录存在该文件时）** + **`--include` 展开列表**（去重）；**不**再自动包含 `MEMORY.md`。需要 `MEMORY.md` 时由 **`--include MEMORY.md`**。与向导「默认 SOUL +（存在的）IDENTITY、不默认 MEM」一致。
- **任意**发布路径在已知 `sourceDir` 后：若 workspace **根目录不存在 `SOUL.md` 文件**，则 **打印明确错误信息并中止进程**（不进入 zip / 上传）。**`--full` 与向导整目录均不例外**。

**非目标**

- 修改 registry API、zip 存储格式或非 CLI 端逻辑（除非为配合文案引用）。

---

## 2. 交互细节（向导）

### 2.1 列表顺序

1. **整个 workspace 目录**（等同 `--full`）— 第一位，默认不勾选。  
2. **根文件多选区**（建议 `SOUL.md` → `IDENTITY.md` → `MEMORY.md` → 白名单其余已存在文件，顺序可与现有一致）。

`IDENTITY.md` 从「extras」中单独成行，不重复。

### 2.2 默认勾选（仅子集模式、可交互项）

| 项 | 行为 |
|----|------|
| `SOUL.md` | 必选，**禁用**取消勾选。 |
| `IDENTITY.md` | 若根目录**存在**该文件：**默认勾选**；若**不存在**：不勾选，**禁用**（文案标明当前根目录无此文件，避免误以为会打入 zip）。 |
| `MEMORY.md` 及其它白名单内文件 | **默认不勾选**。 |

### 2.3 整目录与子集互斥（行为）

- 用户**首次勾选**「整目录」后：**立即进入「整目录展示态」**（实现上可采用 **再次渲染同一类多选** 或等价交互，直至用户确认或改选）：
  - 「整目录」保持勾选；
  - 其余根文件项 **全部 `disabled` + `checked`**（视觉上「全勾选」），表示整包纳入；
  - 用户仅可 **取消整目录** 以回到子集模式；回到子集后恢复 **上一轮子集勾选状态**，若无则按 §2.2 默认。
- **禁止**依赖「整目录 + 其它项同时选中 → `validate` 报错」作为主要互斥手段（用户明确不采纳该文案路径）。

### 2.4 实现提示

若 `@inquirer/prompts` 的 `checkbox` 无法在单次渲染中动态禁用依赖项，可用 **受控循环**（根据是否整目录态重建 `choices`）或 **先选模式再选文件** 仅作备选；**首选**与现有一致的多选心智，以「整目录态」重绘为满足 §2.3。

---

## 3. 非交互默认子集

- 当 **`--full` 未开启**且 **未**由向导提供 `wizardRootFiles` 时，子集为：  
  **`SOUL.md`** + **若 workspace 根目录存在 `IDENTITY.md` 则包含之** + **`--include` 展开列表**（去重）。  
- **不**隐式加入 `MEMORY.md`；需要时：`--include MEMORY.md`。  
- 根目录**无** `IDENTITY.md` 时：子集不含该项（**不**因此报错；仅 `SOUL.md` 缺失按 §4 中止）。

---

## 4. `SOUL.md` 缺失：前置校验

- 在 **`publishPack` / zip 之前**，当 `sourceDir` 已解析且将执行 **整目录或非整目录打包** 时，均执行：  
  `path.join(sourceDir, "SOUL.md")` 存在且为**文件**。  
- 不满足时：**stderr 清晰中文说明**（含路径提示），**以非零退出码结束进程**（`throw` 由 CLI 顶层捕获或统一 `exit`，与现有 CLI 错误风格一致）。

## 5. 文档与对外说明

- 更新 **`README.md` / `docs/DEVELOPMENT.md` / CLI `--help` 描述**：非交互默认子集为 **`SOUL.md` + 存在的 `IDENTITY.md`**（及 `--include`），**不再**写「默认 SOUL+MEMORY」；说明 **`MEMORY` 需显式 `--include` 或向导勾选**。  
- **本节刻意不把 `MEMORY.md` 写成默认必含**（与用户要求「不包括 MEM」一致）。

## 6. 测试建议

- 向导：整目录第一位；勾选整目录后其余项 disabled+checked；取消整目录后恢复默认。  
- 向导：`MEMORY` 默认不勾选；`IDENTITY` 存在时默认勾选。  
- 非交互：无 `--include` 时子集为 `SOUL.md` + 若存在则 `IDENTITY.md`（且 SOUL 存在）。  
- `SOUL.md` 缺失：任意模式均在发布前失败退出。  
- 非交互：`--include MEMORY.md` 仍可将 MEMORY 打入子集 zip。
