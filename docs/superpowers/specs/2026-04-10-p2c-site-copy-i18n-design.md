# P2-C：全站文案与多语言（设计）

**日期**：2026-04-10  
**状态**：已定稿  
**范围**：`web/` — **文案工作**：把 `[locale]` 页面里仍硬编码的字符串 **提取到 `messages`**，并 **按面向用户** 的标准 **改写/润色**（中英）；**不**再搭 i18n 代码骨架。

**关联**：

- 路线图：[`docs/ROADMAP.md`](../../ROADMAP.md) **P2-C**。
- **i18n 基础设施**（路由、`next-intl`、cookie、fallback 等）见 [`2026-04-08-web-i18n-design.md`](2026-04-08-web-i18n-design.md) — **已落地，本 spec 不重述、不改框架**。
- 站点协作入口：[`web/AGENTS.md`](../../../web/AGENTS.md)。

---

## 1. 核心是什么（优先级）

1. **提取与入库**：`src/app/[locale]` 下用户可见文案 → `messages/en.json` + `messages/zh.json`，组件内用 `getTranslations` / `useTranslations` 接好。
2. **文案质量（重点）**：**面向最终用户** — 少内部/开发者说法；与首页语气一致；温柔、帮人挑到喜欢的 Soul；隐私相关 **不吓人**。
3. **产品用词**：用户可见处说 **Soul**，不说 **pack**；中文界面 **Soul** 写拉丁字（见 §2）。
4. 其余（key 命名风格、单文件是否拆分等）**从简**，沿用现有 `home` / `packChat` 的写法即可。

---

## 2. 用词与 Privacy（已定）

- **Soul**：用户向称谓；中文 UI 统一 **Soul**。
- **pack**：仅代码、API、CLI、URL 路径等 **非 UI 产品句** 可保留；**任何用户读得到的句子** 不用 pack 指代上架对象。
- **Privacy**：说明 + 安抚优先，价值在前、细节在后，中英同一策略，避免首屏恐吓式表述。

---

## 3. 非目标

- 改 i18n 路由/middleware、改 `/api/*` 语言策略、把 UGC 塞进 JSON、为文案改公开 URL。
- **P2-B** 首页版式重排非必交付；若顺带润色 `home` 已有 key 以统一语气，可以。

---

## 4. 交付与验收（概要）

- **一轮收完** `[locale]` 范围内面向用户的硬编码串（metadata、按钮、表单、空态、页脚/导航、浏览器内展示的错误提示等）。
- **验收**：主要路径在 `en` / `zh` 下走通且语气、Soul/pack 规则符合上文；可对用户可见文案做一次 **pack 用词** 自检。

---
